## 1. 口径与符号

| 符号 | 定义 | 注意 |
| --- | --- | --- |
| `t` | 比赛时间，开赛为 0，单位 s | 用 `/match/clock`，不用 ROS 时间 |
| `Δ` | `score_opp − score_own`，**正数=落后** | 全项目统一这个符号，避免"领先/落后"写反 |
| `n` | 对手可翻的 L2 塔顶数 | 原文定义；由人工/裁判/感知输入 |
| `k` | `ceil(max(0, Δ) / 160)` | 翻顶追平所需次数；原文"Δ≈255 → k≥2"与此一致 |
| `t0` | 开局从起点到第一个元素 `approach` 的转场 | 单独实测；OPENING 预算必须扣掉它 |
| `t1` | 建 1 座 L1 的耗时（含相邻任务间转场） | p95，实测 ≥10 次 |
| `t2` | 建 1 座 L2 的耗时（含转场） | 同上 |
| `tM` | 取五色石到安放的耗时（含转场） | 同上 |
| `tF` | 抵达并翻转 1 个敌 L2 塔顶的耗时（含转场） | 同上 |
| `margin` | 阶段末保留的安全余量 | 默认 3 s |
| `factor` | 时间估计的安全系数 | 默认 1.20 |

分值（V1）：L1 = 85，L2 = 155，五色石 = 255，翻 1 个敌 L2 顶净摆动 = 160。

## 2. 阶段映射

| 阶段 | 时间 | 策略原文 | 决策层行为 | 进入 | 退出 |
| --- | --- | --- | --- | --- | --- |
| `PRECHECK` | < 0 | 赛前标定 t1/t2/tM/tF，核对规则版本 | 校验配置/地图/定位/时钟/技能；**不通过不动** | 节点 active | 人工开赛 |
| `OPENING` | 0–48 | 最近私有 L1 + 共享 L1；共享位被占 → 私有 L1 + L2 | 生成 2 个建塔任务，按最近优先 | 开赛 | `t≥48` 或两塔完成 |
| `GATE48` | 48 | 保护法则自检；通过→取石，不通过→回建塔 | `DP1`；谓词未定义时 fail-closed | `t≥48` | 决策完成 |
| `STONE` | 48–78 | 立即取石，目标 78 s 前安放 | 取石 + 转场 + 安放（2 个任务） | `DP1=stone` | 安放成功 / `t≥78` |
| `STONE_GRACE` | 78–108 | 78–108 取石超时→弃石 | `DP2/DP3` 二次判断：继续 or 弃石 | `t≥78` 未安放 | 安放成功 / `t≥108` / 判定不值得 |
| `MID` | 78–150 | 建 2 座 L2；持续侦察 n 与 Δ | 2 个 L2 任务；提前完成后用剩余时间 `FILL`（建 L1/抢空位） | 进入 MID | `t≥150` |
| `ASSESS150` | 150 | 终局评估 | `DP4`：计算 Δ、n、k、剩余预算 | `t≥150` | 分支选定 |
| `DEFEND` | 150–165 | 领先且 n≥2：驻防卡位，伺机反翻 | 去防守位 + `wait`/`observe`；反翻需 `flip_top` | `DP4=defend` | `t≥165` |
| `FLIP` | 150–165 | 落后且 n≥k：全力翻敌 L2 顶 | 连续 `flip_top` 任务 | `DP4=flip` | `t≥165` 或完成 |
| `FILL` | 150–165 | 落后且 n<k / 分差小：抢 L2 位或建 L1 | 建 L1 / 抢空位 | `DP4=fill` | `t≥165` |
| `LASTCALL` | 165–177 | 最后决策点；只有剩余 > tF 才允许启动一次翻顶 | `DP5`；预算不够就不启动 | `t≥165` | `t≥177` |
| `FREEZE` | 177–179 | 停止启动 180 s 内完不成的动作 | 不再产生新任务；当前 `ACT` 若能在 179 前完成则允许收尾，否则取消 | `t≥177` | `t≥179` |
| `COOLDOWN` | 179–180 | 蜂鸣前完全脱离夹持 | 零速、退出接触、记录 | `t≥179` | 结束 |
| `FINISHED` | ≥180 | — | 汇总、写日志 | 结束 | — |

> `STONE_GRACE` 不是原文的独立阶段，而是把"78 s 目标 / 108 s 硬弃石"之间的模糊地带显式化：
> 78 s 没安放不立刻放弃，但必须在 108 s 前二次决策。见第 9 节 Q-02。
>
> **MID 的 78–150 是窗口，不是保证**：如果 `DP2` 选择继续取石到 108 s，MID 实际只剩 42 s，
> 按 20% 余量只够建 **1 座** L2（`t2=28.75` 时 1 座约 37.5 s，2 座约 72 s > 42 s）。
> 所以 `DP2` 必须同时判断"继续取石"会不会把 2 座 L2 挤掉；这正是 48–108 这段最容易出错的地方。

## 3. 决策点

### DP0 · 开赛前（不通过就不动）

| 输入 | 通过条件 |
| --- | --- |
| 配置 | `field/policy/skills/robot` 校验通过，版本兼容，地图哈希一致 |
| 定位 | `/reloc_status` 为 `APPLIED/TRACKING`，`applied≥1`，`diff` 达标 |
| 时钟 | `clock_valid=true`，`state=RUNNING` 或允许人工开赛 |
| 技能 | 至少 `navigate` 可用；计划里用到的技能必须可用 |
| 时间常数 | `calibrated=true`；仿真可显式放宽，真机不允许 |

输出：`GO / NO_GO`。`NO_GO` → `FAULT`，不产生任何目标。

### DP1 · `t=48` 保护法则

```
if not protection_law_ok(state):        # 未定义/不通过都走这里
    plan = build_two_towers()           # 回建塔
elif not budget_ok(tM, 30):             # 30 s 窗内做不完
    plan = build_two_towers()
else:
    plan = stone_run()
```

- `protection_law_ok` 是**规则谓词**，不是战术判断；当前规则未给出定义，默认 `False`（fail-closed）；
- `budget_ok(tM, 30)` 见第 4 节：`tM×1.2 + 3 ≤ 30`，即 `tM ≤ 22.5 s`；
- 被抢/被占：由 `world_state` 的元素状态或人工输入触发，进入"逆转"分支（k 由 Δ 估算）。

### DP2 · `t=78` 取石结果

| 情况 | 动作 |
| --- | --- |
| 已安放 | 进入 `MID`，更新比分（本方 +255，`Δ` 相应减少 255） |
| 未安放，且继续不影响 2 座 L2 | 继续取石，硬截止 108 s |
| 未安放，且继续会挤掉至少 1 座 L2 | 按期望值比较：`p_stone×255` vs 一座 L2 的 155；`p_stone < 0.61` 或未知 → 弃石 |
| 石被对手先取走 | 弃石，更新 Δ≈255 → `k≥2`，进入 `MID`，终局优先翻顶 |

"是否挤掉 L2" 的判据：`t_now + tM_remaining + 2×t2×1.2 + margin > 150`。
若成立，说明继续取石后 MID 只剩不到 2 座 L2 的预算（通常只剩 1 座，见第 2 节注）。
这时不能无条件"继续"，要比较石的成功概率与一座 L2 的分值；没有概率数据时按保守值处理（弃石）。

### DP3 · `t=108` 硬弃石

无论是否取到，`t≥108` 一律放弃五色石，进入 `MID`/终局准备。

### DP4 · `t=150` 终局评估

```
k = ceil(max(0, Δ) / 160)
remaining = 177 - 150              # 27 s
if not score_valid or not n_valid: # 输入无效：不猜，走保守分支
    fill()
elif Δ <= 0 and n >= 2:            # 领先/持平且对手有 ≥2 个可翻顶
    defend()
elif Δ > 0 and n >= k and k*tF*1.2 + margin <= remaining:
    flip(k)
elif Δ > 0 and n >= k:             # 想翻但时间不够
    fill()                         # 或抢位；见第 5 节
elif Δ > 0:                        # n < k
    fill()
else:
    fill()                         # 分差小
```

优先级：**硬约束（时间/可达/技能）> 分值期望 > 树上的默认分支**。
即使 `n≥k`，只要 `k×tF×1.2 + margin > 27`，就不进入 `FLIP`，避免"翻到一半时间到"。

### DP5 · `t=165` 最后决策点

- 只允许启动**一次**翻顶；
- 条件：`tF×1.2 + margin ≤ 177 − 165 = 12`，即 `tF ≤ 7.5 s`；
- 不满足就 `retreat / wait`，不再启动不可逆动作。

### DP6 · `t=177` 冻结

- 不再产生新任务；
- 当前 `ACT` 若能在 179 前完成，允许收尾；否则取消；
- 179 前所有技能退出，置 `released=true`。

## 4. 时间预算（硬约束）

这是本文最重要的部分：**策略树能不能打，先看时间预算，不看分值。**

### 4.1 阶段上限

| 阶段 | 可用时间 | 任务数 | 裸上限 | 留 3 s 余量 | 再乘 1.2 安全系数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| OPENING 0–48 | 48 s | `t0 + 2 × t1` | `t0 + 2t1 ≤ 48` | `t0 + 2t1 ≤ 45` | **`t0 + 2.4t1 ≤ 45`** |
| STONE 48–78 | 30 s | 1 × tM | tM ≤ 30.0 | tM ≤ 27.0 | **tM ≤ 22.5** |
| MID 78–150 | 72 s | 2 × t2 | t2 ≤ 36.0 | t2 ≤ 34.5 | **t2 ≤ 28.75** |
| ENDGAME 150–177（k=1） | 27 s | 1 × tF | tF ≤ 27.0 | tF ≤ 24.0 | **tF ≤ 20.0** |
| ENDGAME 150–177（k=2） | 27 s | 2 × tF | tF ≤ 13.5 | tF ≤ 12.0 | **tF ≤ 10.0** |
| LASTCALL 165–177 | 12 s | 1 × tF | tF ≤ 12.0 | tF ≤ 9.0 | **tF ≤ 7.5** |

> 表中 t1 的上限是**按 `t0=0` 反算**的（`t1≤18.75`）；实际必须扣掉开局转场 `t0`。
> 例如 `t0=5 s` 时，`t1 ≤ (48-5-3)/(2×1.2) = 16.67 s`。
>
> 结论：**按 20% 余量规划，四段时间常数必须做到 t1≤18.75（且 t0=0）、t2≤28.75、tM≤22.5、tF≤10（两次翻顶）**。
> 只要有一项明显超，就必须在对应阶段做取舍（弃石/少建一座/只翻一次），不能硬套完整计划。

### 4.2 分值反推的阈值

| 比较 | 条件 | 说明 |
| --- | --- | --- |
| L2 vs L1 | `t2 / t1 < 155/85 = 1.8235` | 单位时间得分更高才建 L2 |
| 翻顶 vs 新建 L2 | `tF < 1.0323 × t2` | 翻顶净摆动 160，略高于 L2 的 155 |
| 翻顶 vs 新建 L1 | `tF < 1.882 × t1` | 160 / 85 |
| 取石 vs L2 | `tM < 1.645 × t2` | 255 / 155；但取石还有 30 s 窗口和规则风险，不能只看比值 |

**这两组阈值可能冲突**：例如 `t2=30, tF=15` 时，分值上 `tF < 31` 成立（翻顶"划算"），
但时间上 `2×15×1.2+3=39 > 27`，两次翻顶根本做不完。**时间约束优先**。

### 4.3 一个具体算例

设实测 `t0=5, t1=20, t2=30, tM=25, tF=15`：

| 阶段 | 预算检查 | 结果 |
| --- | --- | --- |
| OPENING | `5 + 2×20×1.2+3 = 56 > 48` | ❌ 两座 L1 完不成（t0=5 时 t1 必须 ≤16.67） |
| STONE | `25×1.2+3 = 33 > 30` | ❌ 取石超窗（tM 必须 ≤22.5） |
| MID | `2×30×1.2+3 = 75 > 72` | ❌ 两座 L2 完不成（t2 必须 ≤28.75） |
| ENDGAME k=2 | `2×15×1.2+3 = 39 > 27` | ❌ 两次翻顶不可行 |
| ENDGAME k=1 | `15×1.2+3 = 21 ≤ 27` | ✅ 只能翻一次 |
| LASTCALL | `15×1.2+3 = 21 > 12` | ❌ 165 s 时不能再启动翻顶 |

**这组数说明**：原文的"完整计划"（两 L1 + 取石 + 两 L2 + 终局两翻）要求非常激进的执行速度；
如果实测接近这组数，正确做法是**开局就放弃取石或减少 L2**，而不是到 150 s 才发现翻不完。
决策层要在每个决策点用**当前实测 p95** 重算，不能写死"先取石再建两座"。

> 这也回答了原文《02 奇思妙想》的 Q-02（"翻 2 个 L2 顶未算时间成本"）：
> 在 150–177 的 27 s 内翻 2 个顶，要求 `tF ≤ 10 s`（含转场）。达不到就只能翻 1 个或改抢分。

### 4.4 标定方法

| 常数 | 起点 | 终点 | 注意 |
| --- | --- | --- | --- |
| `t0` | 开赛瞬间车的位置 | 第一个元素 `approach` 位 | 只测一次路线；开局姿态固定时可复用 |
| `t1` | 上一个任务结束位置（或元素 `approach` 位） | 元素状态变 `OWN` | 含相邻任务转场；不含开局 `t0` |
| `t2` | 同上 | 同上 | L2 可能要先上 L1 高台，转场时间要算进去 |
| `tM` | 车在石 `approach` 位 | 石安放完成 | 含取、转场、放；不含 48 s 等待 |
| `tF` | 车在敌 L2 `approach` 位 | 翻顶完成并脱离 | 含对齐；不含返程 |

- 每项 ≥10 次，取 **p95**（不是均值）；
- 记录分段：转场 / 对齐 / 作业 / 验证，便于定位瓶颈；
- 仿真测出的数**不能**直接当真机用（场地、摩擦、底盘都不同）；
- 未标定（`calibrated=false`）时，真机拒绝自动执行定时任务。

## 5. 分支与任务模板

### 5.1 任务模板

| 模板 | 技能序列 | 预估 | 前置 | 成功判据 | 失败处理 |
| --- | --- | --- | --- | --- | --- |
| `T_L1(id)` | `navigate(approach)` → `build_l1(work)` | `t1` | 元素 `FREE`、技能可用、预算够 | 元素状态 `OWN` | 重试 0；同一元素累计失败 2 次 → `UNREACHABLE`（人工可清） |
| `T_L2(id)` | `navigate(approach)` → `build_l2(work)` | `t2` | 同上；高台可达 | `OWN` | 同上 |
| `T_STONE_PICK` | `navigate(stone.approach)` → `pick_stone(work)` | `tM/2` | 石 `FREE`、技能可用 | 夹持确认 | 弃石分支 |
| `T_STONE_PLACE` | `navigate(center.approach)` → `place_stone(work)` | `tM/2` | 已夹持、安放点可达 | 安放确认 + 计分 | 弃石/带回 |
| `T_FLIP(id)` | `navigate(opp.approach)` → `align` → `flip_top` → `retreat` | `tF` | 敌 L2 存在、允许进入、技能可用 | 塔顶状态翻转 | 只翻一次，不重试 |
| `T_DEFEND` | `navigate(defense_point)` → `wait/observe` | 到 165 | 防守位可达 | 到点 | 退回安全位 |
| `T_FILL` | `T_L1(最近空位)` | `t1` | 有空位 | `OWN` | 放弃 |

**注意**：

- `T_STONE_*` 被拆成两段，是为了在 78 s 边界处能独立取消/降级；两段的 `est` 之和应等于 `tM`。
- `T_FLIP` 的 `align` 当前没有后端（见 02），所以真机上 `T_FLIP` 实际不可执行；仿真用 `sim_mock`。
- `T_DEFEND` 只能"停在防守位"，**没有物理卡位/阻挡技能**；是否允许阻挡要看规则，不能默认。
- 所有 `T_*` 的 `deadline` 由阶段结束时间减去 `margin` 得到，不能晚于 177。

### 5.2 四个终局分支的计划

**分支 A：领先且 n≥2（DEFEND）**

```
[retreat/defense_point, wait(165)]        # 不主动翻顶；若对手露出空档，人工确认后 T_FLIP
```
决策层只能"守位 + 观察"，"伺机反翻"需要人工确认或感知输入。

**分支 B：落后且 n≥k 且时间够（FLIP）**

```
[T_FLIP(opp_l2_1), T_FLIP(opp_l2_2) ...]  # 数量 = min(n, floor((remaining - margin)/(tF*1.2)))
```
每翻一个更新 Δ 和 k；一旦 `k=0`（追平）立即停止，转 `DEFEND/FILL`。

**分支 C：落后且 n<k（FILL）**

```
[T_L1(free_spot)] 或 [抢 L2 空位]
```
优先抢**空置 L2 位**（155 > 85），但必须确认该位可达、未被占；否则建 L1。

**分支 D：分差小（FILL）**

```
[T_L1(最近空位)] ...
```
"分差小"原文没有数值；本设计把它作为 `fill_close` **兜底分支**（defend/flip/fill_behind 都不命中时），
不单独设阈值。若队内要区分"小分差"和"大分差"，再补 `close_delta`（见第 9 节 Q-06）。

### 5.3 起手分支

| 情况 | 计划 |
| --- | --- |
| 共享位可用 | `[T_L1(最近私有), T_L1(共享)]` |
| 共享位被占/堵死 | `[T_L1(最近私有), T_L2(私有)]` |
| 两个私有 L1 都不可达 | `[T_L1(最近的空位)]` + 记录异常，等人工 |

"最近"用当前位姿到 `approach` 的欧氏距离排序，发目标前用 Nav2 规划预检确认可达；
欧氏距离只用于排序，不作为可达性依据。

## 6. 重规划与优先级

| 触发 | 影响 | 处理 |
| --- | --- | --- |
| 共享位被占 | 起手分支 | `DP` 内切换 L1+L2；不重排已完成任务 |
| 石被抢 | Δ 估算 +255 | `k` 重算；终局优先翻顶 |
| 元素不可达 | 该元素 | 标记 `UNREACHABLE` 30 s，选同阶段下一候选 |
| 定位丢失 | 全部 | 停、取消、等恢复；15 s 未恢复 → `FAULT` |
| 时间超预算 | 当前任务 | 立即弃当前任务，进入下一优先级；不"再试一次" |
| 人工接管 | 全部 | `PAUSED`；恢复后从当前阶段重新评估 |

优先级顺序：`安全 > 时间硬约束 > 必做任务（两塔/取石）> 终局得分 > 防守`。

## 7. 与策略原文的逐条对照

| 原文节点 / 动作 | 本文落点 | 是否可执行 |
| --- | --- | --- |
| 赛前标定 t1/t2/tM/tF、核对规则版本 | `PRECHECK` + `policy.yaml` | ✅ 流程可做，数据待测 |
| 0–48 最近私有 L1 + 共享 L1 | `OPENING` + `T_L1` | ⚠️ 依赖建塔技能 |
| 共享位被占 → 私有 L1 + L2 | `OPENING` 分支 | ⚠️ 依赖建塔技能 + 占用输入 |
| 48 s 保护法则自检 | `DP1` + `protection_law` 谓词 | ❌ 规则未定义；默认 fail-closed |
| 48–78 取石 | `STONE` + `T_STONE_*` | ❌ 无执行接口 |
| 78–108 取石超时 → 弃石 | `STONE_GRACE` + `DP2/DP3` | ✅ 逻辑可做 |
| 78–150 建 2 座 L2 | `MID` + `T_L2`；提前完成则 `FILL` 到 150 | ⚠️ 依赖建塔技能 + 高台可达 |
| 150 领先且 n≥2 → 驻防反翻 | `DEFEND` | ⚠️ 只能守位；反翻需技能 |
| 150 落后且 n≥k → 全力翻顶 | `FLIP` | ❌ 无执行接口；且需规则允许 |
| 150 落后且 n<k → 抢 L2/建 L1 | `FILL` | ⚠️ 部分可执行 |
| 165 最后决策点 | `DP5` | ✅ |
| 177 停止长动作 | `FREEZE` | ✅ |
| 177–180 脱离夹持 | `COOLDOWN` | ⚠️ 需夹持器反馈 |
| 故障/掉落/阻挡 | 安全层 + 重规划 | ✅ 框架可做 |

**结论**：策略原文里，决策层现在能真正执行的只有"时间纪律、阶段推进、导航到点、守位、停"；
所有"建/取/放/翻"都卡在执行接口。这不是决策层能单独解决的，必须和机械/电控一起排期。

## 8. 人工输入降级

在没有裁判接口、没有感知的阶段，`manual_console` 提供最小输入：

| 输入 | 键 | 用途 |
| --- | --- | --- |
| 开赛/暂停/恢复 | `s/p/r` | 驱动 `match_clock` |
| 本方/对方得分 | `+/-`、数字 | 算 `Δ`、`k` |
| 对手 L2 顶数 `n` | `n` | 终局分支 |
| 元素状态 | 选 ID + 状态 | 占用/翻顶 |
| 技能确认 | `c` | `manual_confirm` 后端 |
| 急停 | `e` | 安全层 |

降级规则：

- 输入无效 → 策略走**保守分支**（`FILL` 或 `DEFEND`），不猜；
- 人工接管 → 取消所有自动任务，只保留安全层；
- 人工输入也写日志，回放时可复现。
