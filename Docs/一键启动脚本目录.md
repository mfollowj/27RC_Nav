# 一键启动脚本目录

> 所有脚本都会 `source env.sh`：私有 DDS 域 `ROS_DOMAIN_ID=42`、Gazebo 端口 `11355`。
> 手工敲 `ros2` 命令前也建议先 `source env.sh`。
>
> 2026-10-30 之后：`env.sh` 只认 `Deps/install` + `Nav/ros2_ws/install` + `/opt/ros/humble`，
> 不再 source 任何外部工作区（旧终端里残留的旧工作区前缀会被自动摘掉）。

## 仿真（sim）

| 脚本 | 作用 | 常用参数 | 前置 |
| --- | --- | --- | --- |
| `./sim_map.sh` | 起 Gazebo + 雷达/IMU + 抽稀 + **fast_livo** 建图 | `world:=`、`rviz:=`、`gui:=`、`points_per_frame:=` | 无 |
| `./sim_teleop.sh` | 键盘遥控（发 `/cmd_vel`） | — | `sim_map.sh` 或 `sim_nav.sh` 在跑 |
| `./sim_save_map.sh` | 保存 2D 栅格图 / 3D 点云图 | `map_name:=` | 建图已运行、车走过场地 |
| `./sim_nav.sh` | 用最近一次地图起 **TEASER/GICP 重定位 + fast_livo + Nav2** | `map:=`、`prior_map:=`、`reloc_impl:=`、`teaser_inlier:=` | 已存图 |

仿真建图/导航与真机**同一套** LIO、抽稀节点、重定位链路和参数文件
（`Nav/config/livo_mid360.yaml`），差异只有外参与 `use_sim_time`。

## 真机（real）

| 脚本 | 作用 | 常用参数 | 前置 |
| --- | --- | --- | --- |
| `./real_map.sh` | 建图（FAST-LIVO2 + 抽稀 + 轨迹 + 累积器） | `rviz:=`、`record_traj:=` | 雷达+IMU 已连 |
| `./real_save_map.sh` | 存先验图 + 体检 | `--imu-height 0.30`、`--cloud`、`--traj` | 建图已跑过 |
| `./real_nav.sh` | **6-DOF 重定位 + LIO + Nav2**（默认链路） | `teaser_inlier:=`、`map_voxel:=`、`min_change_trans:=`、`nav2:=` | 已有 `Nav/real/maps/prior_map.pcd` |
| `./real_nav.sh reloc:=false` | 旧 4-DOF 链路（localizer + Nav2） | `initial_pose:=`、`imu_height:=`、`min_score:=` | 已有 2D 地图与先验 PCD |
| `./real_reloc.sh` | 只起重定位链路（调试用包装） | 同 `real_nav.sh` | — |
| `./check_lidar.sh` | 雷达/IMU 频率、时间戳体检 | — | 驱动已起 |

## 常用组合

```bash
# 仿真：建图 -> 存图 -> 导航
./sim_map.sh
./sim_save_map.sh field
./sim_nav.sh

# 仿真：只想看旧的 4-DOF 定位器（A/B 对比）
./sim_nav.sh reloc_impl:=voxel

# 真机：建图（雷达固定、慢速走遍场地）-> 存图 -> 导航
./real_map.sh
./real_save_map.sh --imu-height 0.30
./real_nav.sh teaser_inlier:=15 map_voxel:=0.2

# 真机：只想重定位、先不开 Nav2
./real_nav.sh nav2:=false rviz:=true
```

## 小机器人默认启动（机器人上执行）

```bash
~/SCU27RC_Nav/start_robot.sh            # 驱动 + IMU 翻转 + fast_livo + mcu_bridge
MCU_DRY_RUN=1 ~/SCU27RC_Nav/start_robot.sh   # 串口只打日志不发（第一次上车）
RVIZ=1 ~/SCU27RC_Nav/start_robot.sh     # 机器人有屏幕时顺便开 RViz
```

- 取代原来的 `ros2 launch sentry_bringup position_only.launch.py`（fast_lio + send_data）。
- 雷达是**倒装**的：脚本先起 `cmd_chassis/rot_imu`（/livox/imu → /imu/data，180° roll），
  LIO 订阅 `/imu/data`；共用参数里 `extrinsic_R = diag(1,-1,-1)` 就是对应这个安装方式。
- 机器人上 fast_livo 的 TF 帧名是 `camera_init -> aft_mapped`（不是 odom/base_link），
  所以 mcu_bridge 用 `output_frame:=camera_init`，当前位姿走里程计话题
  `/aft_mapped_to_init`（不依赖 TF）。本机 RViz 的 Fixed Frame 用 `camera_init`。
- 默认 `ROS_DOMAIN_ID=42`（和本机 env.sh 一致），可用 `DOMAIN=0` 覆盖。
- **开机自启**：机器人上是 systemd **用户**服务 `robot-nav.service`
  （`~/.config/systemd/user/`，已 enable；该用户 `Linger=yes`，所以不用登录就会起）。
  管理：`systemctl --user status|start|stop|restart robot-nav.service`，
  日志：`journalctl --user -u robot-nav.service -f`。
  注意它 `Restart=always`：**`pkill start_robot.sh` 会被自动拉起**，要停请用 `systemctl --user stop`。

## 真机串口（mcu_bridge）

把 RViz 里点出的目标点 + 机器人当前位姿发给单片机（15 字节：`7E ID x y yaw 21`，
int32 大端 ×10000）。跑在机器人小电脑上，**独占 `/dev/ttyUSB0`**。

| 命令 | 作用 |
| --- | --- |
| `ros2 launch mcu_bridge mcu_bridge.launch.py dry_run:=true` | 不开串口，只打第一帧 hex（上车第一步） |
| `ros2 launch mcu_bridge mcu_bridge.launch.py` | 真发串口 |
| `ros2 launch mcu_bridge mcu_bridge.launch.py base_frame:=imu_link` | 机器人上跑 SCURM 那套 fast_lio 时用（只发 `odom->imu_link`） |
| `ros2 run mcu_bridge mcu_sniff` | 看串口上的帧（会抢 MCU 的字节，慎用） |

部署（本机 → 机器人）：

```bash
./tools/deploy_mcu_bridge.sh     # rsync 这个包 + 远端 colcon build + 自检
```

> 串口同一时刻只能有一个写者：`send_data`（SCURM 的 `position_only.launch.py` 里
> `respawn=True`）会一直重连，必须改它那个 launch 才能让出 `/dev/ttyUSB0`。

## 退出时会看到什么

- `reloc_bridge` 每 2 秒一行残差；Ctrl-C 后汇总：
  `===== 导航结束：重定位 N 次（首次定位 A / 漂移修正 B）…`
- `laserMapping` 退出汇总：
  `===== 导航结束：先验图播种 N 次，其中重定位重建 M 次 =====`
- `/reloc_status`（String）里是给决策层用的状态机：
  `mode=BOOTSTRAP|SEARCHING|APPLIED|TRACKING …`
